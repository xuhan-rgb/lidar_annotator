# 全帧地图与联合标注

执行方式为三个互斥选项：默认“复用缓存继续执行”按所选阶段检查缓存，变化或缺失时才计算；“复用 SAM，重算后处理”保留已有语义与实例推理结果，强制重做位姿与关联、轨迹选点、位置优化、校验、可视化和标签导出；“重新生成全部结果”清理同一任务旧缓存并从模型推理重新开始，包括 SAM。重算后处理需要相同任务已有的语义、实例及配置；缺少结果或标注配置变化时会提示先用默认方式更新，不会自动调用 SAM。命令行对应 `annotate --refresh-postprocess`，只调度后处理阶段并跳过其阶段缓存。

进度条下方用固定一行显示当前或最近阶段的耗时；鼠标悬停可查看所有阶段的耗时明细；点击旁边的“查看/复制”可打开明细窗口，支持选中文字复制或点击“复制全部”。当前阶段实时累计，完成后保留最终耗时，失败或停止也记录已用时间。计时包含阶段进程启动及缓存校验，复用缓存显示的是本次加载耗时，不是历史推理耗时。运行报告 `run_report.json` 的每个阶段保存 `started_unix`、`finished_unix` 和 `elapsed_seconds`；重新打开软件或切换任务时，默认读取当前任务最近一次运行报告的总耗时和各阶段明细；没有报告时显示暂无记录。旧报告缺少阶段计时时只显示已有总耗时，不推测补算。

“结果可视化”中可切换“查看全帧地图”。该视图读取当前任务所有已处理帧的保存结果，不重新运行 SAM3、检测或目标优化。默认输出流程会在逐帧可视化之后自动生成并保存全帧地图，前提是完整优化结果已经具备；即使逐帧图使用缓存，也会检查地图并补齐缺失缓存。地图生成计入可视化阶段耗时，无需先点击地图页，也不依赖桌面界面保持打开。已有结果仍可在切换地图时直接加载；缺少完整优化结果时跳过地图并记录日志。

地图生成后会保存可直接读取的显示点和 3D 页面。再次打开软件或点击“刷新地图”时，输入及显示范围未变化就复用这些文件，不再逐帧累积或重新导出 3D 页面，底部显示“已读取保存的地图”。修改显示体素间距时，从保存的完整地图重新采样；逐帧语义、实例 mask、优化位置、车辆框、位姿、类别配置或 XY/Z 范围变化时，才重新累积。缺失或损坏的缓存会自动重建。旧版地图没有缓存校验记录，首次使用此功能需生成一次，之后即可复用。

全帧地图、逐帧语义/联合标注和导出标签共用行人支持点筛选逻辑。筛选按固定处理范围、当前帧和行人 ID 执行，用户调整 XY/Z 显示范围只影响绘制，不重新决定哪些点应忽略。地图使用保存的位姿将点云、优化后行人位置及车辆框转换到地图坐标，原始测量点不平移。

行人筛选只作用于原类别为 1、投影在该实例独占 mask 内的可见点。首先读取当前帧的类别确认记录：明确未通过行人类别确认的实例，其原行人点设为 `255` 并记录 `unconfirmed_person_instance`，不会因缺少优化中心又恢复成正式行人标签；未知或缺失的旧元数据不直接视为否定证据。

类别已确认的行人优先保留该帧优化记录中有效的支持点索引，并用当前点团核查：至少 5 个行人点，XY 中位数附近 0.5m 核心至少 5 点且占该组一半，核心中位数距优化中心不超过 0.75m。满足条件时，保留核心中心半径内的点及原有效支持点的并集，其余原行人点改为 `255`。点团不集中时不能无条件保留所有点：保留最终中心周围“核心半径＋允许中心偏差”（默认 1.25m）以内的候选点及已有有效支持点，其余远端原行人点改为忽略，记录 `insufficient_person_core_far_points_ignored`；这一组仍标记待核查。点数不足、可靠点团与中心冲突或优化位置不可用时保留原候选并待核查。半径沿用任务记录的 `reference_tube_m`（默认 0.5m）；不按相对中心的高度剪去头部或腿部，不增加行人点，不修改检测中心、轨迹或其他类别。`ignore` 表示未用于确定的行人语义监督，不是背景负样本。

生成标签时会将相同的行人忽略集合写入 `.label`，同时更新内部 NPZ 的点置信度及相关弱 BEV 标签。每帧 LiDAR JSON 中的 `person_semantic_filter` 记录行人 ID、保留/忽略索引、筛选参数和待核查原因；旧导出保存在工作目录 `label_versions/`，源语义 NPZ、原始点云与图像 mask 保留。仅刷新地图或切换查看模式不会改写已导出的标签。

车辆最终可视化统一采用历史拟合、去重并经多锚几何细化的地图框；逐帧联合标注按当前帧位姿回投这些框。细化读取 temporal 观测、poses 和 history-fit 基线，对每个候选运行 top 8 多锚拟合并以 20% holdout 验证，朝向修正仍限制在原始有向角的 ±90° 以内。通过验证的框覆盖写入 `temporal/map_review/history_fit/bev_dedup/vehicle_map_boxes.npz`，报告保存在 `temporal/map_review/history_fit/multi_anchor/report.json`，旧框保存在其 `backups/` 子目录；验证未通过的候选保留旧框，保留去重后的车辆 ID 和顺序（当前这批数据为 10 个）。它是几何处理，不依赖 OpenPCDet 工程；缓存有效时 optimize 阶段复用已有结果。生成标签与可视化时，车辆框导出和审核图均读取这份最终 NPZ。有最终结果时，即使最终车辆集合为空，也不回退到旧单帧框。尚未生成最终结果时，联合标注才显示已有单帧框，并在状态栏说明。

相机投影点、BEV 和全帧地图共用更新后的车辆点显示：优化三维框内的支持点按车辆类别着色（边界余量沿用优化预览的 0.12m），框外旧车辆语义显示为未知，行人类别优先，框外其他静态类别保持原标签。三维高度也参与选点，不把车下地面仅凭 XY 投影染成车辆。这部分车辆辅助着色仍只用于可视化及地图派生文件；行人的导出语义修订采用上述独立的“原行人→忽略”规则。

“全帧”是当前任务中全部已处理帧。例如 8 帧任务累积这 8 帧，971 帧任务累积这 971 帧。稀疏选帧使用对应帧的原位姿和优化标签，不从其他任务补入目标或点云，不跨缺帧段连采集轨迹。车辆框只保留在这些帧的联合标注显示范围内可见的框。

地图模式隐藏单帧翻页栏。刷新、体素、3D 地图、重置视图及“显示内容”集中在一行工具栏；行人位置标记、行人中心轨迹、车辆框、采集轨迹和起始帧位置的开关收纳在“显示内容”菜单中。青色圆圈、连线和三角形分别是位置、轨迹和起点标记，不是激光点。关闭前两项可以单独检查底图中的行人语义点；这些开关不修改任何标签。

采集轨迹以白色小圆点标出每一帧位置，较大的标记表示起始帧，不绘制逐帧文字和引线。悬停圆点可查看原始帧号及 XYZ 坐标；交互 3D 地图同步显示逐帧位置和独立起点标记。“显示内容”中可分别开关每帧位置和起始帧位置。

行人最终位置读取 `consistent_tracks/final_centers.npz`，采用全局参考 XY 和保留的地图高度；旧射线修正位置保存在诊断文件中。静止目标的全局参考 XY 一致，不再把每帧不同相机射线上的投影位置作为最终中心。当前实例支持点达到 5 个的位置以青色圆圈表示，不足 5 个时以橙色叉号表示“仅轨迹估计”；三维地图也分为两个图例项。起点取该行人最早的有效原始帧，二维用三角形、三维用菱形标记。中心轨迹按同一行人的原始帧号排序，仅连接相邻有效帧，不跨缺帧或位姿分段连线。位置与轨迹标记不属于原始点云；这些显示开关不改写标签。

地图派生文件保存在任务输出目录的 `review/optimized_map/`：

- `map_points.npz`：显示范围内所有参与累积的点、逐点语义及来源帧号，优化后的行人位置和车辆框，以及参与的位姿。
- `display_points.npz`：当前体素间距下的显示点和目标数据，用于再次打开时直接加载。
- `map_3d.html`：离线交互 3D 可视化。
- `report.json`：纳入的帧号、完整点数、显示点数、范围和坐标说明。
- `cache.json`：输入及显示设置的校验记录，用于判断是否可以复用保存的地图。

显示体素默认 0.15m，合并仅用于显示，完整归档保留每个点。设为“全部点”可不做显示合并。地图位姿来自记录里程计，目标标注来自保存的优化结果；地图生成不执行额外的 SLAM 或点云配准，也不改写训练标签。
